# Dependeasy performance completion — 28 October 2026

This follow-up implements artifact ownership, configuration reuse, compatible lazy configuration and bounded automatic history collection, and measures the actual routed invocation. The first lazy-analysis model subtype was withdrawn after live reader compatibility failed. The subsequent implementation keeps the existing `Process` wire format and now passes real compilation and repeat-build qualification. Both experiments remain separately identified below. The original [September/main benchmark](../dependeasy-benchmark-2026-10-28/report.md) remains unchanged. Its exclusive-worker numbers and older current revision must not be pooled with the secondary-slot experiments.

## Implemented changes

- The analysis adapter retains the existing serialized `Process` spec. Compiler/runtime configuration identities stay declared; a Java argument file is generated by the existing task action. Exporting unrelated nodes no longer needs to resolve those analysis classpaths. Real compilation, configuration-cache reuse and exact repeat class bytes pass. The incompatible subtype from the earlier experiment remains withdrawn.
- JVM and multiplatform JVM libraries publish their existing JAR task and archive through `JvmLibrary`. The ordinary graph and Gradle invocation own the build; no parallel scheduler is added.
- Reaktor now defaults to `org.gradle.configuration-cache=true` after the actual JAR-plus-export invocation passes cold/store, ordinary reuse, a real Kotlin body edit, and build-declaration invalidation checks. This changes the Reaktor root; it does not enable the default in BestBuds or Manna.
- The router consumes the declared JVM public output only when its producer participated successfully. It returns large declared archives, preserves containment and source/provenance checks, and excludes unrelated JARs and class/resource trees. Its existing router fixture checks an archive larger than 8 MiB.
- JavaScript package, asset and runtime metadata use deferred providers while retaining their producer dependencies. The existing export/install/edit fixtures pass; this does not remove all work needed to serialize a selected web contract.
- Automatic success and failure collection filters protocol history by the current worker start time. Model/host evidence remains included; explicit `pull` retains the full historical view and no worker history is deleted. The new router/build/retention suite passes 69 cases, including 90 old plus three current protocol records.

## Interpretation and remaining performance work

The artifact change addresses output ownership and transfer cost. It does not remove the settings/build-logic/project-configuration regression found against September. The compatible argument-file implementation now avoids unused analysis resolution without a new model subtype. The controlled continuation below finds no material timing gain from its three lazy-configuration production files on this core-JAR workload. Configuration reuse supplies the largest demonstrated warm-path gain.

The compiler's KT-62686 fallback is a distinct upstream limitation, present in both original stacks. JetBrains' [separate-compilation announcement](https://blog.jetbrains.com/kotlin/2026/09/a-more-reliable-compilation-scheme-for-kotlin-multiplatform-modules/) introduces an experimental solution in Kotlin 2.5 and documents C-interop issues. This project pins 2.4.21. Do not enable an unsafe incremental bypass or silently upgrade the compiler as a performance shortcut. Qualify a future toolchain change against actual platform and incremental-output correctness.

Configuration reuse is implemented and requalified on the final compatible core-JAR invocation. Cold bootstrap, ordinary admission queues, bounded history reads, representative Android/web/native targets and application→service→Hangar tracing remain separate measurements. A faster core JAR does not certify those dimensions.
