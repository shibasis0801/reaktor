This is the single execution roadmap for `reaktor-cli`, `reaktor-code`, `reaktor-conductor` and `reaktor-tooling`, including Dependeasy and Hangar integration. The [code/agent HLD](code-agent-hld.md) and [CLI/kernel HLD](cli-kernel-hld.md) specify architecture; [token ROI analysis](token-roi.md) retains the landscape, accounting implementation and historical evidence. Their former implementation sequences are superseded here.

## Decisions

1. Build one graph-native capability system with small, composable operations and concern-owned executable tools. Kotlin clients, native agent shells, MCP, CI and Hangar invoke the same domain behavior and retained state.
2. Make `reaktor` a thin workspace-kernel client. Dependeasy owns all shared build tooling: declarations, toolchain contracts, generation, compiler/bundler integration, packaging, build verification and CI/local-worker build policy. Gradle and specialist tools execute its artifact plan. CLI, Hangar, CI and wrappers delegate; target/script guessing is retired as real paths migrate.
3. Deliver continuity, bounded context, strong input identity and reusable check receipts before an exhaustive semantic graph. Existing code lookup, language servers and native tools supply the first useful answers.
4. Adopt SCIP as a candidate semantic-index interchange/provider, qualified per language and compilation. Use a validated Kotlin semantic adapter where needed. Joern is an optional deeper flow-analysis engine, admitted for a demonstrated investigation after measurement.
5. Keep provider indexes independently versioned behind Reaktor capabilities. The existing graph remains the identity/ownership foundation. No third universal database, temporary competing control plane or future Graph-v2 rewrite is required.
6. Tools live inside their concern modules: code/agent scripts, adapters, recipes, launchable assets and Kotlin integration. Generic process/transport infrastructure stays in tooling; shared build algorithms and packaging policy belong to Dependeasy. Source ownership of an asset does not create a competing build implementation.
7. Active rollout is Reaktor, BestBuds and Manna only. Other repositories wait until all three meet the build owner's stability gate. Use expressive declarative profiles for common work, with typed backend/native/custom-task access in the same artifact graph for exceptions. One owner/tool per responsibility; pnpm-only installs, Vite-only owned JS bundling, SwiftPM/direct Xcode Apple integration, and removal of replaced paths at qualified cutover.
8. Integrate A2A in Conductor for Claude/Codex communication through qualified native-session adapters. Reuse existing collaboration/handoff records and shared authority, expose peer operations through MCP, CLI and typed clients, and bound model turns and message exchanges. A2A is not another task database or a reason to route every operation through MCP; the [A2A design](code-agent-hld.md#a2a-between-native-claude-and-codex) defines protocol/domain mappings and retry limits.

## Review of the Joern + SCIP proposal

The supplied [proposal](</Users/ovd/.codex/attachments/af75924a-0542-47d4-839b-1f78a85e96ba/Pasted text.txt>) is source material, not an instruction to execute its commands or expose its server. Its central separation is useful. Its blanket ranking over Graphify, CodeGraph or Serena is unproven for this workspace: no matched provider benchmark or live KMP semantic qualification has been performed here.

| Proposal | Decision and correction |
|---|---|
| SCIP navigation plus Joern control/data flow | Adopt the separation. SCIP is a protocol; answer quality comes from the indexer, configuration, dependency metadata and indexed scope. A reference is not automatically a resolved call or behavioral dependency. |
| Kotlin is supported | Qualify JVM, common, Android, JS and Native separately. The [scip-java documentation](https://github.com/scip-code/scip-java/blob/main/docs/getting-started.md) calls Kotlin less mature and lists Android Gradle integration as unsupported. Successful emission of a file does not prove correct references. |
| July modernization makes scip-java ready | The [0.13.0 release](https://github.com/scip-code/scip-java/releases/tag/v0.13.0) merged scip-kotlin and changed ownership/artifact coordinates; [0.13.1](https://github.com/scip-code/scip-java/releases/tag/v0.13.1) followed on July 2. Later [Kotlin fixes](https://github.com/scip-code/scip-java/pull/973) merged July 17, including Kotlin 2.4.0 updates. Distinguish the pinned release from later main-branch changes. |
| Kotlin 2.3 / Gradle 9 reports establish current incompatibility | The cited [issue #864](https://github.com/scip-code/scip-java/issues/864) reproduced older 0.12.3/SemanticDB components. It is a qualification warning, not proof that current code fails identically. Test the upgraded Reaktor toolchain without downgrading it to fit an indexer. |
| Joern understands KMP semantics | Its [published table](https://docs.joern.io/#supported-languages) rates Kotlin and Swift medium maturity. Treat Joern-derived calls/flows as frontend-dependent static analysis. Compiler-resolved facts remain separate; a validated Analysis API/LSP adapter is required before claiming unsupported KMP semantics. |
| Joern 4 is sufficiently cheap | The [Flatgraph migration](https://github.com/joernio/joern/blob/master/changelog/4.0.0-flatgraph.md) reports memory/traversal improvements on particular workloads. Those figures do not predict Reaktor cost. Measure cold indexing, warm queries, update cost, RSS, storage and worker transfer. |
| Commit/checkpoint always refreshes Joern | Reject automatic analysis on every checkpoint or commit. A checkpoint records continuation. Deep analysis requires a question, supported scope and budget. The [Java incremental proposal](https://github.com/joernio/joern/issues/5865) is not proof of general incremental KMP support. |
| Successful compilation always refreshes SCIP | Use declared provider-specific index stages when requested or economically justified. scip-java's default indexing command can clean and compile; never attach that default to an ordinary read or every build. Other indexers have different triggers. |
| Join source ranges and symbols; preserve provenance | Adopt with stronger identity and explicit ambiguous/unmapped joins, as specified below. Commit/module/variant alone is unsafe for dirty worktrees and different compiler inputs. |
| Five agent-facing analysis tools | Map useful capabilities into typed `code.query` variants. Do not add five competing root tools or require call/data-flow support to ship navigation. |
| Cache one baseline across Shadow agents | Share matching immutable artifacts. Give mutable worktree indexes and query state separate ownership. Changed files can alter resolution outside the file; a small delta alone does not prove valid whole-module flow results. |
| Connect Kotlin → binding → native entrypoint | Add producer-attested FFI mappings when the generator/build owner can supply them. Cross-language names, ranges or runtime observations alone do not prove one logical relationship. Version custom external-call summaries and keep missing paths visible. |
| Expose Joern through an adapter | Required. The [server](https://docs.joern.io/server/) exposes an interpreter and provides no sandbox. Admit predefined queries with validated parameters, isolated execution and bounded results; never pass agent-authored Scala to it. |

The comparative choice is therefore an engineering judgment to validate: **existing lookup/LSP first; qualified SCIP/Kotlin semantics next; Joern for questions needing deeper analysis.** Graphify, CodeGraph and Serena remain alternatives for a specific measured gap, not mandatory dependencies or additional concurrent indexing stacks.

## Ergonomic operation contract

These are proposed public semantics; names become executable only after the slice wires and tests them. Ordinary precise file/editor/build tools remain usable, with resulting candidates/evidence observed and attributed.

| Family | Minimal operation surface | Agent experience |
|---|---|---|
| Task | `task.open`, `task.context`, `task.checkpoint` | Attach to an existing outcome, obtain the next useful bounded packet, retain decisions and next action with expected-revision checks |
| Peer | `peer.discover`, `peer.send` | Qualified peer discovery and bounded typed notification/question/handoff/delegation; shared run/artifact access, current evidence and explicit model-work budget |
| Code | `code.query` | Typed find/outline/references/impact; later calls/data-flow when supported; explicit evidence requirement and compilation scope |
| Change | `change.plan`, `change.apply` | Review a retained exact diff/recipe plan; apply by returned reference against matching inputs |
| Check | `check.start` | Execute or safely reuse explicit required checks; accepted handle or completed receipt |
| Run | `run.read`, `run.wait`, `run.cancel` | Retained state, bounded server wait/revision cursor, cancellation acknowledgment/reconciliation |
| Artifact | `artifact.read` | Revision-bound pages of source, diffs, diagnostics and logs |

Task creation/model submission remains with the existing explicit task owner. Opening a task or retrieving context does not create another task or launch a model. `task.context` composes relevant code/build/check evidence in one bounded read so the agent need not orchestrate many tiny calls.

CLI common verbs are `status`, `build <target>`, `check <target>`, `dev <target>` and `open <reference>`, with the families above and advanced `tools`/`workspace` groups. Canonical `code.query` can project to shell `code query` and MCP `code_query`; the same serializers and validators define both. Help lists relevant capabilities, not every script or provider. Environment is explicit request scope; reads never change Hangar's selection. One existing workspace-root convention (`--dir`, compatibility mapping for `--workspace`) has one meaning.

Resolve workspace, roots, candidate/input manifest, compilation, environment and authenticated caller once. Return that scope, completed/accepted/rejected delivery, domain outcome, completeness, evidence/provenance, omissions and expandable handles. Unknown/ambiguous/stale/unsupported requests return stable structured errors with a remedy. Missing semantics cannot silently become a complete text answer. Parser recognition and required-check execution coverage are different dimensions.

Machine stdout is one bounded valid JSON value; progress goes to stderr. Invalid inputs fail before effects, redirected stdin cannot supply policy approval, and required-check failure/incompleteness cannot exit as complete success. Helpers retain request IDs/plan/run references for retry; agents do not calculate hashes or reconstruct compiler argv. Deduplication binds caller/workspace/operation/request ID to the same payload; conflicting reuse rejects. Lost replies and owner restart must not duplicate effects.

Bound aggregate serialized output before materialization, deduplicate excerpts, and keep full logs/index graphs in artifacts. Token estimates remain estimates. A response too small to carry its protocol envelope is rejected; JSON is never truncated. Durable waiting/detachment happens in the client/service, avoiding repeated model polling. Client exit or Hangar closure detaches; only acknowledged owner cancellation establishes termination.

## Source facts, provider artifacts and invalidation

Extend existing occurrence/candidate/evidence models only as each consumer needs them. The attachment's `SourceAnchor(repo, commit, path, range, buildVariant)` is insufficient. An adapter needs canonical repository/workspace and worktree identity, exact file content digest, explicit coordinate encoding, compilation identity and input manifest, plus provider/version/options and index snapshot. Commit is useful provenance, not dirty-source identity. Provider symbol addresses are qualified within their artifact/compilation; preserve known rename lineage and authored Reaktor IDs.

Normalize positions at the boundary. The [SCIP schema](https://github.com/scip-code/scip/blob/main/scip.proto) carries document position encoding and symbol roles/relationships. Handle UTF-8 bytes, UTF-16 or UTF-32 units explicitly, normalize to the chosen code contract, and test Unicode, multiline/end boundaries and stale file versions. Current code-span behavior and proposed half-open ranges must be reconciled, not silently reinterpreted.

Retain relation kind, evidence strength, resolution status, provider snapshot and coverage separately. Join indexes through exact content/compilation, verified symbol mapping and source/enclosing ranges; multiple matches remain ambiguous. Conflicting provider facts coexist with provenance. A Joern possible-call edge never overrides a compiler reference; neither implies an observed runtime call. FFI joins use generated contract/export IDs and attested producer artifacts with ABI/target identity. Unmapped boundaries remain explicit.

Cache keys cover relevant dirty source and dependency artifact digests, declarations/configuration/flags, compilation and toolchain, provider/frontend/options, rules or external-flow summaries, query/check/recipe versions. A manifest with weak/unknown inputs cannot authorize application or check reuse. Checks additionally declare execution environment, external-state assumptions and freshness/reuse policy; live service/device observations cannot be reused solely because source hashes match. The earlier equal-size large-file probe demonstrates why size/mtime/HEAD alone is inadequate. Safely reuse existing digest infrastructure; include directory membership/deletion and dependency invalidation, not just modified file hashes.

Build indexes into temporary owned output, validate completion/coverage, then publish immutable artifacts atomically. A crash, omitted source set, bad classpath or partial index must not appear as a complete empty answer. Cache matching immutable baselines across tasks; deduplicate index builds through the existing run owner. Isolate mutable overlays/worktree state. Retention and byte limits use existing artifact lifecycle; delete reproducible unreferenced artifacts, never active source/evidence. For Joern, re-run all required passes and dependent scope or construct a fresh scoped CPG unless the pinned frontend proves safe incrementality.
